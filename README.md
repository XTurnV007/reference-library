# 本地参考图书馆

**生图提交已按用户要求恢复**：原图统一使用支持跨域读取的 raw 地址，原图不可读时停止提交，不以预览图替代。请求不自动重发；实际出图仍未进行付费验证。详见 [当前状态](IMAGE_API.md)。

在线图库：<https://xturnv007.github.io/reference-library/> · 源码：<https://github.com/XTurnV007/reference-library>

已发布 2,846 张图片记录及其原图、预览版本。公开图库无需本机持续运行；共享点击统计需要另外部署统计 API 并在发布时配置地址。

新版入口为创作平台，支持参考图选用、私人上传、草稿、作品和外观设置；原有图库保留在 `gallery.html`。GitHub 版通过云端转发调用 ugq.ai 多参考图编辑接口，密钥由用户在设置页填写，逐张显示真实结果，无需启动本地程序。详见 [云端转发说明](CLOUD_RELAY.md)、[生图接口与使用说明](IMAGE_API.md) 和 [平台使用说明](PLATFORM.md)。

需要公开部署到 GitHub Pages 时，请阅读 [发布说明](PUBLISH.md)。静态版将预览图放在 Pages、原图统一放在支持跨域读取的独立资源分支；个人标记仅保存在浏览器。

点击趋势、热门排行榜和共享统计 API 的使用及部署见 [统计说明](ANALYTICS.md)。本地站重启后即可使用；公开静态站需单独配置统计服务。

采集指定的姿势库和服装库，在本地网页中管理图片。Python 3.10+，仅使用标准库，无需 pip、Node 或前端构建。

本项目按照远程磁盘工作方式编写：代码已保存，**尚未在远程服务器运行、下载图片或执行测试**。下面的命令由你通过 SSH 执行。所有相对命令均在服务器上的 `AIIP/reference_library` 目录执行；Windows 的 `F:` 挂载路径不是服务器的实际路径。

## 1. 进入目录并检查环境

### 在 Windows PowerShell 直接运行

如果在挂载盘 `F:` 中直接启动，请使用 Windows 的真实 Python。此机器上 `python` 指向 `G:\python311\python.exe`，而 `python3` 指向 WindowsApps 别名；应使用 `python`。

```powershell
cd F:\start_your_own_bussiness\self_media\AIIP\reference_library
python --version
python server.py --port 8765
```

启动后终端应显示「打开 http://127.0.0.1:8765」，并持续运行，不会立即回到 `PS ...>` 提示符。直接在这台电脑浏览器打开该地址即可，无需 SSH 隧道。先只输入服务启动这一条命令；测试命令请在另一个终端执行，或先按 Ctrl+C 停止服务再执行 `python -m unittest -v`。

若挂载盘不支持 SQLite 或文件锁，请把运行数据放到 Windows 本地目录，采集和服务均使用同一路径：

```powershell
python server.py --port 8765 --data "$env:LOCALAPPDATA\AIIP-reference-library"
```

此时网页发起的采集会把图片和数据库一起保存到该本地目录。下面的 `python3` 示例针对通过 SSH 连接的 Linux 服务器；在 Windows 中使用 `python` 替代。

### 在远程 Linux 服务器运行

```bash
# 把下方路径替换成远程服务器上 AIIP 的真实路径
cd /你的实际路径/AIIP/reference_library
python3 --version
```

要求 Python 3.10 或更新版本，SQLite 启用 JSON 函数（大多数发行版内置）。若服务器的 `python` 已指向 Python 3.10+，也可用 `python` 替代 `python3`。

## 2. 启动网页管理

```bash
python3 server.py --port 8765
```

服务绑定 `127.0.0.1`。**在自己电脑另开一个终端**建立隧道，替换 SSH 用户及地址：

```bash
ssh -N -L 8765:127.0.0.1:8765 用户名@服务器地址
```

保持服务和隧道运行，在自己电脑浏览器访问 <http://127.0.0.1:8765>。本地和远端端口均用 8765。若需换端口，服务命令和隧道两端一起改为同一个端口。

点击右上角「采集图片」，选择两个图库或单个图库。界面每 4 秒读取进度，新原图下载后自动刷新列表；查看详情或批量选择时会保留当前操作。采集期间页面可以关闭，服务进程必须保持运行。关闭服务会中断网页发起的后台采集，下一次重新采集即可续传。若希望 SSH 断开后继续运行，可在服务器已有的 tmux/screen 会话中启动。

## 3. 也可先在命令行采集

```bash
# 全量采集：两个图库，保存所有原图、预览图、缩略图
python3 crawler.py --source all

# 分开采集
python3 crawler.py --source pose
python3 crawler.py --source costume

# 仅保存原图，网页可直接以原图展示，加载可能较慢
python3 crawler.py --source all --originals-only

# 放慢请求速度；默认 3 个下载线程，全局每 0.5 秒发起一个请求
python3 crawler.py --source all --workers 2 --delay 1
```

两个站点的完整清单分别来自 `data/pose-zh.json` 和首页的 `const D` JSON 数组；程序不执行远程 JavaScript，不依赖页面分页。默认采集清单列出的全部图库图片版本，不采集 logo、社交分享封面等页面装饰。数量以每次实际清单为准，不使用固定编号猜测图片地址。新增图片会在重跑时入库；原站移除的旧图片与本地标记仍保留，不自动删除。

每次重新采集都会刷新清单，并检查已有文件是否存在、大小是否匹配，跳过完整记录、补齐缺失项及失败项。下载使用有限重试、超时、请求间隔和 robots.txt 规则，遇到 429/临时错误退避重试。原图失败时不会偷偷以缩略图代替。失败记录可在网页按「下载失败」筛选。返回非图片错误页会记为失败。CLI 存在失败时以退出码 1 退出；两个站点中任一个失败，不阻止尝试另一个。任务完成进度包含跳过的已有文件，失败数计入已处理总数。

网页和 CLI 共用操作系统文件锁，禁止同时运行两个采集任务。若进程被强制结束，锁会由操作系统释放；新采集会把旧的运行记录标记为中断。任务初次请求失败可能要等待超时重试后才显示错误。站点结构变化时程序会明确报错，不会将空清单覆盖原有收藏。

## 管理功能

- 按来源、分类、体系、视角、下载状态筛选，搜索名称、ID、关键词、标签和备注。
- 分页浏览、懒加载、原图查看与下载；同组姿势可切换视角，左右键切换当前页图片。
- 单张或批量收藏，设置标签，保存备注。批量标签操作会**替换**所选图片的已有标签。
- 回收站仅隐藏索引，支持恢复，不删除图片文件或回收磁盘空间。
- 导出当前筛选下的**全部记录**到 JSON，不受当前页限制。导出含来源元数据、标签、备注与状态；该文件是索引导出，不含图片，也没有导入接口。
- 图库在已采集完成后可断网使用；页面没有外部字体、CDN 或图片热链。

## 数据与备份

默认保存到本项目 `data/`，也可以通过所有程序的 `--data` 参数或环境变量 `REFERENCE_LIBRARY_DATA` 改位置。采集、服务、校验必须使用同一个目录。

```bash
python3 crawler.py --source all --data /服务器本地磁盘/reference-data
python3 server.py --data /服务器本地磁盘/reference-data --port 8765
python3 verify.py --data /服务器本地磁盘/reference-data
```

建议把运行数据放在服务器本地磁盘，而不是再次挂载的远程文件系统上，以保证 SQLite 和文件锁可靠。项目不启用 WAL。

```text
data/
  library.sqlite3           # 图片索引、标签、备注、收藏、回收站、任务进度
  images/ab/<sha256>.png    # 按内容哈希去重，扩展名按实际图片格式识别
  catalogs/pose.json        # 最近一次解析的清单快照
  catalogs/costume.json
  crawl.lock               # 持续保留的锁文件，不需要手动删除
```

同一张图片的不同格式仍是不同文件；内容完全相同的文件只存一份。完整备份时先停止采集和服务，再复制整个 `data/`。勿只备份 SQLite 而遗漏图片。

## 校验与测试（由你执行）

```bash
# 离线回归测试：只使用临时目录与模拟响应，不访问源站
python3 -m unittest -v

# 全量 SHA-256 校验
python3 verify.py

# 把损坏文件标记为失败，再运行采集修复
python3 verify.py --repair
python3 crawler.py --source all
```

校验发现异常时返回退出码 1，`--repair` 只标记记录，修复下载由下一次采集完成。默认续传仅检查存在与大小；同样大小的内容损坏要用 SHA-256 校验发现。图片下载验证文件签名，不执行完整像素解码。测试覆盖清单解析、拒绝站外地址、保留人工标记、URL 更新失效、去重、续传、错误页拒绝、文件缺失与校验修复、搜索通配符以及编辑和路径边界。浏览器布局与实际全量下载尚待运行验证。

手动验收建议：启动后采集一个图库，确认进度和图片出现；收藏一张图、编辑标签与备注，重启服务确认仍保留；移入回收站后恢复；重跑采集确认已有文件被跳过；在浏览器断网状态浏览已下载图片。首次全量下载耗时和空间取决于原站图片体积及网络，未预设容量估计。
